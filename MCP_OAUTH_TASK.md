# ТЗ: OAuth для MCP-сервера бота

Задание на отдельную сессию. Цель — чтобы дневник подключался как обычный
коннектор в claude.ai и Claude Desktop: «Добавить коннектор» → адрес → согласие
→ готово. Ни терминала, ни правки JSON, ни репозитория, ни Node.js.

## Зачем это вообще

Сейчас доступ по MCP закрыт статическим bearer-токеном (`db.mcp_tokens`,
выдаётся на экране `/mcp`). Это работает в клиентах, которые умеют слать
произвольный заголовок: Claude Code, Cursor, VS Code, Claude Desktop через
мостик `mcp-remote`.

Чего так не сделать: **браузерный claude.ai и нативные коннекторы Claude
Desktop статический токен не принимают** — им нужен OAuth. А это ровно тот
сценарий, где пользователь ничего не настраивает руками, то есть единственный
по-настоящему массовый.

Итог задачи: оба способа работают одновременно. OAuth — для обычных людей,
статический токен — для тех, кто живёт в терминале, и он **не должен сломаться**.

## Что уже есть

| Файл | Что там |
| --- | --- |
| `mcp_server.py` | MCP-сервер: 11 read-only инструментов поверх `ai_trainer.execute_tool`, белый список `READ_ONLY_TOOLS`, проверка bearer-токена, `serve()` под uvicorn |
| `db.py` | Таблица `mcp_tokens` и функции `issue_mcp_token` / `get_mcp_token` / `revoke_mcp_token` / `resolve_mcp_token` |
| `handlers/mcp_access.py` | Экран `/mcp`: выдача, отзыв, инструкции под каждый клиент (`GUIDES`) |
| `keyboards.py` | `mcp_keyboard`, `mcp_guide_keyboard`, список `MCP_CLIENTS` |
| `config.py` | `MCP_PUBLIC_URL`, `MCP_PORT`, `MCP_ENABLED`, `mcp_available()` |
| `main.py` | Запуск сервера рядом с поллингом, в том же процессе |
| `tests/test_mcp_*.py` | 34 теста: границы токена, протокол по проводу через ASGI, экраны |

Сервер задеплоен и работает: `https://<домен>/mcp` отвечает `401` без токена.

## Пользовательский сценарий, к которому идём

1. Человек в claude.ai жмёт «Добавить коннектор», вставляет `https://<домен>/mcp`.
2. Claude сам регистрируется как OAuth-клиент и открывает нашу страницу согласия.
3. На странице — что именно отдаётся (список данных) и поле «код из Telegram».
4. Человек идёт в бота, `/mcp` → «🔗 Код для подключения», получает 6 цифр на 5 минут.
5. Вводит код, жмёт «Разрешить» — редирект обратно, коннектор подключён.
6. На экране `/mcp` появляется список подключённых приложений с кнопкой «Отключить».

Код из Telegram — это способ узнать, кто перед нами, без пароля и регистрации:
единственный аккаунт у пользователя бота — телеграмный, и подтвердить владение
им он может только через сам бот.

## Архитектура

SDK (`mcp==2.0.0`) закрывает протокольную часть. Всё ниже проверено на
установленной версии, имена реальные.

**Что даёт SDK.** `MCPServer(auth_server_provider=..., token_verifier=...,
auth=AuthSettings(...))` сам поднимает роуты:

- `/.well-known/oauth-authorization-server` — метаданные AS (RFC 8414)
- `/.well-known/oauth-protected-resource/mcp` — метаданные ресурса (RFC 9728)
- `/authorize`, `/token`, `/register` (RFC 7591), `/revoke`

Он же валидирует PKCE, проверяет `redirect_uri`, разбирает гранты и
навешивает на `/mcp` middleware, требующее валидный токен.

**Что писать самим** — провайдер `mcp.server.auth.provider.OAuthAuthorizationServerProvider`:

| Метод | Что делает |
| --- | --- |
| `get_client` / `register_client` | Хранение клиентов (динамическая регистрация) |
| `authorize(client, params)` | Вернуть URL страницы согласия; параметры запроса сохранить, чтобы после согласия собрать редирект |
| `load_authorization_code` / `exchange_authorization_code` | Код → пара токенов |
| `load_refresh_token` / `exchange_refresh_token` | Обновление, с ротацией обоих токенов |
| `load_access_token` | Токен → `AccessToken` |
| `revoke_token` | Отзыв токена и парного к нему |

`exchange_identity_assertion` не трогать: дефолт отвергает грант, и это верно.

Импорты: `AuthorizationParams`, `AuthorizationCode`, `RefreshToken`,
`AccessToken`, `OAuthToken`, `AuthorizeError`, `TokenError`, `RegistrationError`
— всё из `mcp.server.auth.provider`. Настройки —
`mcp.server.auth.settings.AuthSettings` вместе с `ClientRegistrationOptions(enabled=True)`
и `RevocationOptions(enabled=True)`.

**Страница согласия** — свой роут через `MCPServer.custom_route(path, methods)`.
`GET` рисует форму, `POST` проверяет код и редиректит на `redirect_uri` с
`code` и `state`. Разметку держать в отдельном модуле или в тройных кавычках
рядом — шаблонизатор ради двух страниц подключать не надо.

**Кто пользователь внутри инструмента.** Сейчас `_call` достаёт токен из
заголовка сам. С OAuth это заменяется на
`mcp.server.auth.middleware.auth_context.get_access_token()` → `AccessToken.subject`,
куда провайдер кладёт `telegram_id`. Один путь получения `user_id` на оба вида
токенов — статический тоже должен приходить как `AccessToken` с тем же
`subject` (см. ниже про `TokenVerifier`).

## Схема БД

Четыре таблицы в `SCHEMA` (`db.py`), рядом с `mcp_tokens`. Все на удаление по
владельцу — «отключить приложение» должно гасить всё, что с ним связано.

```sql
-- Клиенты динамической регистрации (RFC 7591). Регистрируется приложение
-- (Claude, Cursor), а не человек, поэтому user_id тут нет.
CREATE TABLE IF NOT EXISTS oauth_clients (
    client_id TEXT PRIMARY KEY,
    client_secret TEXT,
    metadata TEXT NOT NULL,      -- OAuthClientInformationFull в JSON
    created_at TEXT NOT NULL
);

-- Код авторизации: живёт минуты, гасится при обмене.
CREATE TABLE IF NOT EXISTS oauth_auth_codes (
    code TEXT PRIMARY KEY,
    client_id TEXT NOT NULL,
    user_id INTEGER NOT NULL,
    redirect_uri TEXT NOT NULL,
    redirect_uri_provided_explicitly INTEGER NOT NULL,
    code_challenge TEXT NOT NULL,
    scopes TEXT NOT NULL,
    resource TEXT,
    expires_at REAL NOT NULL
);

-- Выданные токены. refresh_token в той же строке: отзыв одного обязан
-- гасить парный, а держать их порознь — это способ про это забыть.
CREATE TABLE IF NOT EXISTS oauth_tokens (
    access_token TEXT PRIMARY KEY,
    refresh_token TEXT UNIQUE,
    client_id TEXT NOT NULL,
    user_id INTEGER NOT NULL,
    scopes TEXT NOT NULL,
    resource TEXT,
    expires_at REAL NOT NULL,
    created_at TEXT NOT NULL,
    last_used_at TEXT
);

-- Одноразовый код из бота, которым человек доказывает, кто он.
CREATE TABLE IF NOT EXISTS oauth_link_codes (
    code TEXT PRIMARY KEY,
    user_id INTEGER NOT NULL,
    expires_at REAL NOT NULL,
    attempts INTEGER NOT NULL DEFAULT 0
);
```

Индексы по `oauth_tokens(user_id)` и `oauth_auth_codes(expires_at)`.

Миграции не нужны: таблицы новые, `CREATE TABLE IF NOT EXISTS` в `SCHEMA`
достаточно (см. как заводился `mcp_tokens`). Одноразовые миграции
`_run_one_shot_migrations` не трогать.

## Флоу согласия

1. `authorize(client, params)` складывает параметры запроса в короткоживущую
   запись (тот же `oauth_auth_codes` до подтверждения либо отдельная таблица
   pending-запросов — на усмотрение, но состояние должно переживать
   перезапуск контейнера) и возвращает URL вида `/consent?request=<id>`.
2. `GET /consent` рисует страницу: имя приложения из метаданных клиента,
   перечень отдаваемых данных, поле для кода, кнопки «Разрешить» / «Отмена».
3. `POST /consent` сверяет код: не истёк, не исчерпал попытки, существует.
   Верный код → гасим его, создаём `AuthorizationCode`, редиректим на
   `redirect_uri` с `code` и `state`. Неверный → та же страница с ошибкой и
   `attempts + 1`.
4. Дальше клиент идёт на `/token`, всё остальное делает SDK.

Код в боте: кнопка «🔗 Код для подключения» на экране `/mcp`, шесть цифр,
TTL 5 минут, живёт один. Показывать оставшееся время не надо — достаточно
написать «действует 5 минут».

## Совместимость со статическим токеном

Здесь легче всего сломать то, что уже работает.

1. **`require_token` из `mcp_server.py` удалить.** Сейчас эта ASGI-обёртка
   требует токен на *любом* запросе. С OAuth она отрежет `/authorize`, `/token`,
   `/register` и оба `.well-known` — то есть весь флоу. Её работу берёт на себя
   `RequireAuthMiddleware` от SDK, который навешивается только на `/mcp`.
2. **Написать `TokenVerifier`**, принимающий оба вида токенов: сперва искать в
   `oauth_tokens`, при промахе — в `mcp_tokens`. Оба случая возвращают
   `AccessToken(token=..., client_id=..., scopes=[...], subject=str(user_id))`.
   Для статического токена `client_id` осмысленно поставить `"static"`, а
   `expires_at` не выставлять — он бессрочный, пока не отозван.
3. **`_call` и `_user_id` переписать** на `get_access_token().subject`.
   Разбор заголовка руками уходит целиком.
4. `AuthSettings.issuer_url` и `resource_server_url` берутся из
   `config.MCP_PUBLIC_URL`. Без HTTPS OAuth не поедет — на Amvera он есть.

Проверка, что не сломали: существующие тесты в `tests/test_mcp_server.py`
(вызов инструмента по статическому токену, 401 без токена, изоляция чужого
токена) должны проходить **без правок логики**. Поправить в них можно только
то, что связано с исчезновением `require_token`.

## Экраны и инструкции в боте — обязательная часть задачи

Это не «допилить потом». OAuth без обновлённых инструкций бесполезен: человек
по-прежнему увидит на экране только токен и указание лезть в конфиг, то есть
ровно то, от чего мы уходим. Задача не считается сделанной, пока экран `/mcp`
не рассказывает про новый способ.

Что должно измениться в `handlers/mcp_access.py` и `keyboards.py`:

**Главный экран.** Сейчас он открывается словами про токен. Теперь первым идёт
простой путь: «в Claude и других приложениях бота можно подключить как
коннектор — вставить адрес и подтвердить кодом». Токен остаётся, но ниже, как
вариант для тех, кому нужен терминал.

**Новая кнопка «🔗 Код для подключения»** — выдаёт шестизначный код на 5 минут.
Текст экрана: сам код крупно, что он одноразовый, куда его вводить.

**Новая инструкция «☁️ Claude в браузере»** (шестой пункт в
`keyboards.MCP_CLIENTS` и `GUIDES`): открыть настройки коннекторов, добавить
свой, вставить адрес `https://<домен>/mcp`, на странице согласия ввести код из
бота. Без единого файла конфигурации.

**Переписать инструкцию Claude Desktop.** Сейчас там мостик `mcp-remote` и
требование Node.js — с OAuth это больше не нужно: Desktop подключает коннектор
нативно, тем же способом, что и браузер. Нативный путь становится основным,
вариант с `mcp-remote` оставить внизу одной строкой для старых версий.

**Раздел «Подключённые приложения»** на экране `/mcp`: имя клиента, дата
подключения, последнее обращение, кнопка «Отключить» на каждое (гасит все
токены этого клиента для этого пользователя). Без него человек не может
отозвать доступ у конкретного приложения, а «перевыпустить токен» на OAuth не
влияет — это разные механизмы, и молча делать вид, что кнопка отзыва по-прежнему
закрывает всё, нельзя.

**Что не трогать:** инструкции для Claude Code, Cursor и VS Code. Для них
bearer-токен по-прежнему самый короткий путь, и ломать работающее ради
единообразия не надо.

Требования к текстам те же, что и к существующим: каждая инструкция влезает в
одно сообщение Telegram (лимит 4096 символов, на это есть тест
`test_guide_fits_into_one_telegram_message`), в конце — то, что нужно
скопировать, и как проверить, что получилось.

## Безопасность — чеклист

- PKCE обязателен, `code_challenge_method=S256`; проверку делает SDK, но
  `code_challenge` обязан сохраняться и сверяться при обмене.
- `redirect_uri` — точное совпадение с зарегистрированным, без префиксов.
- Код авторизации одноразовый: гасить в той же транзакции, где обменяли.
  Повторный обмен — `TokenError("invalid_grant")`.
- TTL: код авторизации ≤ 5 минут, access ≈ 1 час, refresh — недели, с ротацией
  на каждом обмене.
- Код связывания: 6 цифр, `secrets.randbelow`, не более 5 попыток, TTL 5 минут,
  гасится при успехе. Без лимита попыток шесть цифр перебираются за минуты.
- Токены в базе лежат в открытом виде, как и `mcp_tokens` — это осознанно
  (у нас нет отдельного хранилища секретов), но новых мест утечки быть не
  должно: **не логировать значения токенов и кодов**, ни в `logger.info`, ни в
  сообщениях об ошибках.
- Отзыв: `revoke_token` гасит и access, и парный refresh.
- Прополка просрочки: удалять истёкшие коды и токены в `admin_tasks` рядом с
  чисткой `shared_items` — иначе таблицы только растут.
- Данные отдаются те же и только на чтение: белый список `READ_ONLY_TOOLS` не
  расширять. Ни `get_full_chat_history`, ни пишущих инструментов.

## Тесты

Отдельный файл `tests/test_mcp_oauth.py`, стиль как в существующих
`test_mcp_*`: тестируем границы, а не то, что функция что-то вернула.

Обязательно:

- полный флоу по проводу: регистрация клиента → `/authorize` → согласие с
  кодом → `/token` → вызов инструмента выданным токеном → в ответе данные
  этого пользователя;
- refresh: обмен даёт новую пару, старый refresh больше не работает;
- код авторизации нельзя обменять дважды;
- чужой `redirect_uri` отвергается;
- неверный PKCE-верификатор отвергается;
- код связывания: истёкший не подходит, после 5 неверных попыток не подходит и
  верный, использованный не подходит второй раз;
- «Отключить приложение» убивает и access, и refresh;
- статический токен продолжает работать (регресс на существующее поведение);
- токены и коды не попадают в логи (caplog).

Гонять запросы через ASGI, как уже сделано в `tests/test_mcp_server.py`
(`_running` + `_asgi_post`), без поднятия реального сокета.

## Ручная приёмка

1. `https://<домен>/.well-known/oauth-authorization-server` отдаёт JSON с
   `authorization_endpoint` и `token_endpoint`.
2. В claude.ai добавить коннектор по адресу `https://<домен>/mcp`, пройти
   согласие с кодом из бота, спросить «покажи мои последние тренировки» —
   данные приходят.
3. То же в Claude Desktop как нативный коннектор, без `mcp-remote`.
4. Claude Code со старым статическим токеном продолжает работать.
5. «Отключить» в боте → коннектор в claude.ai перестаёт отвечать.

## Известные грабли

Это уже стоило времени один раз, повторять не надо:

- **DNS-rebinding.** В `build_app` защита выключена явно
  (`TransportSecuritySettings(enable_dns_rebinding_protection=False)`). Без
  этого параметра SDK включает её сам со списком из одного localhost, и за
  прокси хостинга всё отвечает `421`. При правке `build_app` не потерять.
- **Stateless.** Сервер поднят с `stateless_http=True, json_response=True`:
  контейнер перезапускается когда угодно, состояние сессии держать негде.
- **Порт.** Один процесс, порт 80, рядом с поллингом (`main.py`). Второй
  процесс к той же SQLite не подключить — база на единственном соединении.
- **Облачные сессии Claude Code** ходят через egress-прокси и рубят чужие
  домены с `403`, пока домен не добавлен в allowlist окружения. К OAuth
  отношения не имеет, но при отладке путается с ошибкой авторизации.

## Отдельная мелочь, не связанная с OAuth

В инструкции для VS Code (`handlers/mcp_access._vscode_guide`) сейчас только
проектный `.vscode/mcp.json`. Добавить глобальный вариант: палитра команд →
**MCP: Add Server** → **User settings** — чтобы человеку без открытого проекта
не приходилось его заводить.
