# Подключение дневника как MCP-сервера

Бот отдаёт свои данные наружу по MCP (см. `mcp_server.py`). Здесь — как подключиться
к нему клиентом. Про сам сервер и что именно он отдаёт — докстринг в `mcp_server.py`.

Токен выдаётся в боте: команда `/mcp` → «Выдать токен». Один живой токен на человека,
перевыпуск гасит прежний.

## Локально (обычный путь)

Ничего из этого репозитория не нужно — достаточно одной команды, её же показывает
экран `/mcp` с уже подставленными адресом и токеном:

```bash
claude mcp add --transport http -s user training-log \
  https://<адрес-бота>/mcp \
  --header "Authorization: Bearer <токен>"
```

## Из облачных сессий Claude Code

Здесь нужны обе половины, по отдельности ни одна не работает.

**1. Конфиг сервера — `.mcp.json` в этом репозитории.** Локальные `claude mcp add`
пишут в `~/.claude.json` на машине, а в облачную сессию едет только то, что лежит в
репозитории. Токен в файл не подставляется: он берётся из переменной окружения
`TRAINING_LOG_MCP_TOKEN`, иначе уехал бы в git открытым текстом. Адрес по умолчанию
зашит, переопределяется через `TRAINING_LOG_MCP_URL`.

**2. Домен бота — в allowlist окружения.** Облачные сессии ходят через egress-прокси,
который по умолчанию пускает только пакетные реестры и GitHub; чужой хост он рубит
с 403. На claude.ai/code → иконка облака над полем ввода → шестерёнка у окружения:

* **Network access** → `Custom`
* **Allowed domains** → адрес бота, одной строкой
* отметить **«Also include default list of common package managers»** — без этого
  отвалятся pypi и github, и сборки в сессиях сломаются
* **Environment variables** → `TRAINING_LOG_MCP_TOKEN=<токен>`

Политика и переменные применяются к новым сессиям, текущую надо перезапустить.

Значения переменных окружения видны всем, у кого есть доступ к этому окружению —
для личного окружения приемлемо, для общего лучше не надо.
