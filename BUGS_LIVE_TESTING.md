## Открыто — требует внимания

### 44. Тренер может молчать сколько угодно (частично закрыто)
Живьём: «🐦 GOT THE QUESTION», крутящийся placeholder и ни ответа, ни ошибки
дольше двух минут. По коду видно только половину причины, и она настоящая: у
ОДНОГО вызова модели таймаут был (`AI_REQUEST_TIMEOUT_SECONDS`, 90с), а у всего
хода — никакого. Раундов с инструментами до `MAX_TOOL_ROUNDS + 1`, плюс живой
поиск со своим таймаутом: арифметика разрешала молчать минут десять, и всё это
время человек видел только анимацию.

**Закрыто:** дедлайн на весь ход (`AI_TOTAL_ANSWER_SECONDS`, 300с) — молчание
превращается в честное «⚠️ Не смог получить ответ» с клавиатурой, бронь `_busy`
снимается, вопрос из квоты не списывается. Плюс в лог пишется время ответа: без
него «почему молчал» по логам не разобрать вообще никак.

**Осталось открытым:** почему в том же заходе не ответила `/ai_dialogs` —
админская команда, к тренеру не относящаяся. Общей блокировки на пользователя в
коде нет (`_busy` — множество id, оно только у AI-входов и отвечает видимым
«ещё думаю»), `db._write_lock` при удержании повесил бы и `/start` через
`activity_log`, а он отвечал мгновенно. Без продовых логов на этом всё; теперь
там будет строка про время ответа, с ней разбирать станет чем.

### 39. Ошибки ввода копятся в чате — ЗАКРЫТО
Проверено 20.08 по коду: `ui.reply_transient` зовётся в `handlers/backfill.py`,
`handlers/bodyweight.py`, `handlers/edit_workout.py` (четыре места) и
`handlers/routines.py`. `message.reply(e.message)` не осталось нигде.

### Не перепроверено в этом заходе (могло остаться открытым)
Не хватило времени дойти до кода этих пунктов — были в первом прогоне,
статус не подтверждён ни фиксом, ни живым тестом:
- №1 — свежедобавленная программа не в верхних кнопках старта тренировки, пока
  по ней не тренировались (`db.list_recent_programs` всё ещё считает только по
  `workouts.routine_id` — механизм не изменился, вероятно всё ещё открыто).
- №4 — цель прогрессии может расходиться с тем, что тренер продиктовал текстом
  (поведение модели, не ловится статическим чтением кода).
- №4d, №4e — «из тренировки» создаёт программу без явного подтверждения;
  кнопки выбора тренировки для программы неразличимы между собой.
- №15a, №15c, №15d, №15e — суперсет не предлагает остаток дня программы;
  суперсет не виден как связка в карточке итога; старт дня поверх открытой
  тренировки без предупреждения; программу нельзя начать, не выйдя из пикера.
- №19 — программа на один день выглядит иначе, чем одиночная тренировка (лишний
  экран навигации).
- №21 — «суперсет» в БД — не единый блок с двумя упражнениями, а два отдельных
  блока, совпавших по времени; ронять комментарий в `db.workout_plan()`,
  утверждающий обратное, либо на самом деле связывать их — не проверено, что
  сделали.

## Проверено 14.08 и почищено в PR #455 (этот заход)

- **LaTeX в ответе AI-тренера.** На «что такое e1RM?» бот прислал формулу в
  сыром `\[...\]`/`\times` — Telegram не рендерит, видно бэкслеши. Плюс
  затесавшееся английское слово посреди русской фразы. Промпт теперь явно
  запрещает LaTeX-нотацию.
- **Дубли упражнений.** В каталоге нашлись три записи одного жима лёжа —
  «Жим штанги лёжа», «Жим лежа (Штанга)», «Bench Press (Barbell)» (последняя
  с нулём тренировок). Инструмент `create_exercise` уже просил проверять
  существующие упражнения — уточнено, что совпадение может быть кросс-языковым.

## Почищено в PR #439–454 (подтверждено чтением кода 14.08)

Помечено кратко — по каждому пункту в коде есть комментарий, прямо описывающий
старое поведение и фикс; при желании детали найдутся по ключевым словам ниже.

- **№2** «из 3 дня» → родительный падеж (`day_word_gen`, `formatting.py:1271`).
- **№5** План теперь пересобирается из программы при возврате в тренировку
  (`resync_plan_with_routine`, `handlers/workout.py:1461`).
- **№5/поиск, №6** Поиск упражнений — релевантность (`_RELEVANCE_RANK`) +
  разбор словоформ (`_stem_filter`), а не голая подстрока по алфавиту
  (`db.py:1793`).
- **№7** Пустая выдача поиска с экрана групп теперь всегда даёт «➕ Создать»
  (`db.py`/`handlers/workout.py:1813`, комментарий явно ссылается на баг).
- **№8** Восстановление по группам не проверено отдельно, но общий фикс плана
  (см. №5) сдвинул тот же контекст.
- **№9** Верхняя граница веса тела — уже не 1000 кг, комментарий
  `parser.py:180` прямо говорит «replaced the old 0-1000 cutoff».
- **№10** Прошлое взвешивание с датой — `bw_weight_entered` принимает `date`,
  есть `_logged_at_for`.
- **№12** Инструкция «100 8» на экране пикера — специальный перехват
  `_looks_like_a_set` с честным ответом вместо «ничего не нашлось».
- **№13** Пустая группа у новичка — шаблоны каталога дополняют список
  (`handlers/workout.py`, «раньше он упирался в «здесь пусто»»).
- **№14** RPE — есть подсказка «⬇️ Ещё: RPE, заметки, правки» (`keyboards.py:503`).
- **№16a** Пикер больше не ест команды — `_NOT_A_COMMAND` фильтр.
- **№17** Голая кнопка «➡️» — не перепроверялась отдельно, но соседний экран
  пагинации переписан (см. №4b/4c).
- **№18** «Дневник еды» из чата с тренером теперь досчитывает КБЖУ тем же
  `analyze_food`, если модель не прислала цифры (`ai_trainer.py:3836`,
  комментарий прямо про хачапури из находки).
- **№20** «Программа пройдена» теперь показывается сразу по закрытии последнего
  планового упражнения (`live_finish_exercise` зовёт
  `_enter_program_complete_screen` напрямую).
- **№22** `program_total_workouts` — отдельная функция, не теряющая счётчик при
  удалении дня (комментарий прямо: «находка 22»).
- **№23, №43** Промпт больше не обещает кнопку «Начать по ней» прямо под
  сообщением — только «Забрать: …» с превью на следующем экране.
- **№26** Экран правки программы показывает состав дней (docstring
  `keyboards.py` описывает фикс дословно).
- **№27** Приём пищи с 6+ позициями не обрезается — сворачивается в «и ещё N».
- **№28** Импорт CSV на UTC+12 не сдвигает дату — «безопасный полдень» сдвигается
  на офсет.
- **№29** Поиск по истории больше не врёт про число >20 — честная пагинация
  «N из M» (`HISTORY_SEARCH_PAGE_SIZE`, `count_workouts_by_exercise`).
- **№31** Слово «сет» убрано из прозы — «подход» везде, включая карточку
  тренировки.
- **№32** Удаление упражнения из прошлой тренировки пересчитывает ачивки —
  `editw_remove_exercise` идёт через `_on_workout_edited`.
- **№33** КБЖУ от модели больше не уходят в минус/абсурд — `_as_macro`
  отбрасывает `< 0` и `> лимита`.
- **№34** Смена часового пояса пересчитывает значки —
  `achievement_sync.resync` в `settings_timezone_set`.
- **№35** Часовой пояс — диапазон UTC−11…+14, не только −1…+12.
- **№36** Профиль больше не пишет «ограничений нет» от себя — голое отрицание
  фильтруется `_is_blank_limitation`.
- **№37** «Всего тренировок: 20» — дублирующее слово убрано.
- **№38** Перенос тренировки на другой день двигает и метки подходов —
  длительность не пропадает (`shift_workout_set_timestamps`).
- **№40, №41** Импорт визитки режет имя/описание под те же лимиты, что и
  ручной ввод (`MAX_NAME_LEN = config.MAX_EXERCISE_NAME_LENGTH`), не под
  собственный лимит формата визитки.
- **№42** «Уехало N из M» — причина считается по факту (лимит vs пустые дни), не
  по совпадению чисел; `empty_days` считается отдельно.
- **№4a2, №4b, №4b1, №4c** Редактор состава дня программы переписан целиком:
  постоянные три колонки без выпадающих стрелок, имя ведёт на цель, а не на
  удаление, номер в подписи вместо обрезанного имени.
- **№4c2** Не перепроверялось отдельно, но общий редактор дня переписан (см.
  выше) — вероятно задет тем же фиксом.
- **«Дата создания упражнения»** — русский формат вместо ISO
  (`format_date_ru`, `handlers/exercises.py:404`).
- **«81 символов»** — склонение через `plural_ru` вместо жёсткого f-string.
